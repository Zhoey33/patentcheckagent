# 专利审查 skill 优化记录

2026-09-14，参考 [handsomestWei/patent-disclosure-skill](https://github.com/handsomestWei/patent-disclosure-skill)。只借鉴其结构和工作方法，未复制工具代码或安装其依赖。

## 参考仓库的适用部分

- 以简短 `SKILL.md` 路由到具体规则，按需读取参考资料。
- 申请文件模块把权项、说明书和附图做语义对照，并强调机器对照不等于公开充分。
- 将内容缺口与已确认事实区分，保留原材料依据，避免凭空补造技术事实。

交底书生成、轻量查新、外观线稿、Obsidian 案例库、专利地图与审查意见答复不属于本系统当前的申请材料检查任务，未引入。参考仓库的 OA 模块也包含 PDF 文本抽取，并非不经文件工具就能读扫描件，因此没有沿用其扫描件限制。

## 当前内容的实际问题与改动

| 原有内容 | 问题 | 新规则 |
|---|---|---|
| 说明书必须逐字重复每条从属权利要求，术语不能差一个字 | 把文字重合误当支持关系 | 检查语义、对象和技术关系，只有影响理解/范围时报告差异 |
| 所有功能限定、模型、数值范围都要求固定披露清单 | 不区分公知实现及实际技术贡献，容易误报 | 按实现所需信息判断，说明本案为什么需要某项细节 |
| 要求保证新颖性、体现发明点 | 无对比文件也可能给出实体否定结论 | 无经核实对比证据时明确未评估，不凭部件常见否定组合 |
| 缺少材料时直接套清单 | 未上传与原申请缺失混淆 | 区分未提供、未读完、未找到与已证实问题 |
| 泛泛要求“具体条款”，包含旧条号和地方习惯 | 容易生成错误条号或扩大适用范围 | 提供官方依据入口，未知条款或地方版本明确待核实 |
| 请求用户提供文本，运行前固定解析 | 与原文件交给 Codex 的目标不符 | skill 指导 Codex 自行读文件及查看扫描页，保留可读性边界 |
| 两份 277 行正文并存，使用时拼接 prompt | 内容重复维护，也不是真正的 skill 调用 | 单一 skill 包：入口、权项检查、说明书检查、报告格式、依据边界 |

新版位于 `skills/check-patent/`。两阶段保留，通过稳定特征编号连接；修改规则后，任务应保存完整 skill 快照，以保证执行中不受编辑影响。

## 行为验收重点

1. 文本型 PDF、扫描件 PDF 和 Word 均从原文件交给 Codex；不能只因没有文字层在上传时失败。
2. 不同表述但语义一致的说明书支持不能误报为“未逐字复制”。
3. 只做温度数值显示的方案，不应凭标题“提示”就要求添加报警功能。
4. 只有公知部件而没有对比文件，不应直接给出不具备新颖性的结论。
5. 真正缺少引用基础或存在图文矛盾时，应给出具体原文、位置和修改方向。
6. 不可辨读或未读完的页面，应列出范围限制，不能伪装完成全文检查。

上述是用于行为复核的案例条件，不是已完成测试的声明；真实调用结果在部署验收后记录。
