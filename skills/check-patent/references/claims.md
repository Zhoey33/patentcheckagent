# 权利要求检查

## 形式、范围与引用关系

- 核对权项编号、引用对象是否在前、依赖关系是否循环，多项从属引用是否为择一以及是否存在多项从属相互依赖。
- 核对主题和保护对象、必要的技术关系、限定对象和先行引用基础。文字、符号、公式有歧义时结合上下文判断，不仅匹配关键词。
- 检查一个权项是否清楚构成一个完整技术方案；不因省略公知细节就认定缺少必要技术特征，也不擅自把标题中的“提示”等词解释为必须具备报警功能。
- 引用基础针对技术对象及其关系，不要求常用属性、部位或方位先单独定义。例如已引入“壳体”后使用“壳体背面”，通常已有对象基础；仅当实际存在多个不同对象或方位导致技术关系不确定时报告。
- 数字与标点按可辨读原图和上下文理解。字体字距形成的空格不等于数值歧义；清晰的相邻数字“1 7”可读为“17”，不能凭空补出小数点或并列分隔符。只有原图确实无法辨认关键字符时列为读取限制。
- 普通几何尺寸可按本领域通常测量含义理解，不机械要求全部补写测量仪器、状态或步骤。仅当材料涉及多种会改变数值的状态、特殊测量方法，且上下文不能确定时形成待核对项。
- “例如、约、等、预设、用于、配置为”等词只触发语义检查。指出具体导致范围不确定或无法实现的原因，不能直接按禁词定性。
- 同一对象命名不一致时指出两处位置和实际歧义；有明确同义定义且未改变范围时可以通过。
- 产品、方法、系统、介质等布局按已有方案评估，不要求每案强制补齐所有保护主题。名称长度、段落写法等形式要求须有适用依据，不能用模板偏好作为拒绝理由。

## 技术特征清单

每个独立权项建立自己的特征编号；每个从属权项列出新增限定和继承路径。摘录应保留量词、连接关系、范围端点和逻辑条件。

对可能需要解释的内容，说明本案需要确认什么以及为什么：

| 内容 | 核对重点 |
|---|---|
| 自定义术语、相对词 | 定义、判断标准或足以消除歧义的上下文 |
| 功能性限定 | 实现该功能所需的具体手段及所概括范围的支持；公知实现方式不机械要求重新披露 |
| 上位概括或并列替代 | 说明书能否合理支持整个范围，不能仅按实施例数量判断 |
| 数值、参数、范围 | 含义、单位、测量/确定方式以及与方案的关系；端点和中间例是否必要取决于技术性质和范围宽度 |
| 算法或模型 | 涉及技术贡献的输入、输出和关键处理关系；仅在方案需要时核查训练、架构及数据条件 |
| 结构或连接 | 部件之间的位置、连接、配合与运行关系，以及相关附图 |
| 与技术效果相关的特征 | 技术手段、所解决问题和效果之间的可解释关系 |

本阶段只形成支持性核对清单。只有已阅读相关说明书内容，才能对其支持情况作有依据的判断。
